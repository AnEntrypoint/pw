1. What it is

pw installs playwriter 0.9.0, the npm package from remorses/playwriter, and gives each project its own Chrome profile.

The browser does not start at agent start. It starts on the first tool call or CLI command. It stops after 5 minutes with no traffic. The idle time is set by PLAYWRITER_IDLE_MS, which defaults to 300000 milliseconds.

A stop is a clean Browser.close, so cookies are flushed. The profile is kept at <project>/.playwriter/browser-profile.

2. Install

You need git, Node 22 or later, and a Chrome or Chromium. git is needed because npm fetches the GitHub package. If no browser is found on first use, the gate runs playwriter browser install, which downloads Chrome for Testing into ~/.playwriter/browsers.

There is one install command. It needs only add-mcp, which runs through npx:

npx -y add-mcp "npx -y github:AnEntrypoint/pw" -n playwriter --all -g -y

-g is user level. --all writes into every agent add-mcp supports. For one agent only, use -a claude-code instead of --all.

add-mcp takes the quoted command string, so it runs npx -y github:AnEntrypoint/pw for each agent.

Options

Options go through add-mcp, after the install command:

OptionUse
--env PLAYWRITER_NO_SANDBOX=1Needed in Linux containers, where Chromium's sandbox is blocked.
--env PLAYWRITER_IDLE_MS=600000Changes the idle time, in milliseconds. This value is 10 minutes.
--env PLAYWRITER_TELEMETRY=0The relay sends anonymous usage stats (version, OS, arch, command counts; no code, URLs or page data) by default. This turns that off.
npx -y add-mcp "npx -y github:AnEntrypoint/pw" -n playwriter --all -g -y --env PLAYWRITER_NO_SANDBOX=1

The sandbox is a security layer of Chromium. Set PLAYWRITER_NO_SANDBOX=1 only where the sandbox is blocked.

3. What the install does

  • add-mcp writes an MCP entry named playwriter. Its command is npx -y github:AnEntrypoint/pw.
  • npx fetches this repo, installs its one dependency (playwriter 0.9.0), and runs the bin playwriter-project. The first run takes about 40 seconds for that.
  • The first tool call starts the gate for the project. The gate starts Chrome when a request arrives.

4. Modes

playwriter-project has these modes:

ArgumentsMode
noneMCP server bound to this project's browser. Agents run this mode. Use it in .mcp.json.
startOpen this project's browser now. It also opens on first use.
status [--json]Show this project's gate, every Chromium browser on this machine, and this project's pages. It does not start the browser.
session [flags]Create a CLI session bound to this project's browser.
helpPrint the usage.
any other argumentsRun playwriter <args> bound to this project's browser.

MCP mode connects straight to the gate. It does not use the relay.

CLI commands are different. A CLI session is held by playwriter's relay, which listens on port 19988, starts on demand, and is shared by every playwriter CLI user on the machine. The relay reaches Chrome through this project's gate, because session passes the gate address to playwriter as --direct.

Feedback on each call

In MCP mode, every tool result ends with one extra text block. Its first line is this project's gate. Then one line lists every Chromium browser on the machine, and the pages of this project's browser sit under its own line:

playwriter-project /work/app: gate pid 4321 port 9534, debug port 10034, browser running pid 4322 (gate), leases 1
browsers: 2 open on this machine (scan 41 ms)
  pid 4322, owner this project's gate pid 4321, profile /work/app/.playwriter/browser-profile, debug port 10034, pages 1, windows 2
    page 3F2A9C0D1B8E4F6A7C5B2D1E0F9A8B7C about:blank "about:blank"
  pid 1059177, owner gate pid 985903 for /workspace/oscraft, profile /workspace/oscraft/.playwriter/browser-profile, debug port 9931, pages 4, windows 6

The tool list gains one entry, browsers. A reply that carries no result passes through unchanged.

Status

playwriter-project status prints the same block. status --json prints the gate pid and port, the debug port, the profile, the browser pid, whether the gate started the browser or adopted it, whether the browser is running, the lease count with the pid of each lease holder, and the pages. Each page has an id, a title and a URL. Only pages are listed, not workers or service targets. The JSON also has a browsers list of every browser on the machine.

With no gate running, status says so and exits 0, and the browser list is still shown. In JSON it reports "gate": null.

Browsers on this machine

A process counts as a browser when its program is Chromium or Chrome and it has no --type= argument. That leaves out renderer, GPU and helper processes. Linux reads /proc. macOS runs ps. Each browser gets one line:

  • the pid and the owner: this project's gate, another project's gate with its project path, or none, which means the browser was not started with a pw profile;
  • the profile directory, or default when the browser has no --user-data-dir;
  • the debug port, when --remote-debugging-port is in its arguments;
  • the page count from /json/list, when that port answers;
  • the window count from xdotool search --pid, when DISPLAY is set and xdotool is installed. Without xdotool the line has no window count. A busy X server can make a count read 0.

The scan is cached for 2 seconds in each MCP process. Each probe waits at most 700 ms, and the probes run in parallel, so a tool call waits about one second at most for the block.

The browsers tool

Each MCP session lists a browsers tool next to execute and reset. It takes action, target and force.

CallResult
action: "list"Returns every browser as JSON.
action: "close", target: "project"Closes this project's browser through its gate, the same way the idle stop does. Refused while another lease is held, unless force is true. The refusal lists the lease pids. The calling session's own lease does not count. An adopted browser is refused.
action: "close", target: "pid:<n>"Closes a browser only when its pid is the one this project's gate started, the pid in .playwriter/browser.pid. Any other pid is refused, and the refusal names its owner: another project's gate with its path, a default or other browser, or an adopted browser. The lease rule applies too.

The reply is JSON: the action, the target, what was closed, what was refused and why, and the browser list after the close. The status block after the reply shows the same new state. The tool never closes a page. Closing a browser ends its tabs.

{
  "action": "close",
  "target": "pid:1059177",
  "closed": [],
  "refused": [{ "target": "pid:1059177", "reason": "pid 1059177 belongs to gate pid 985903 for /workspace/oscraft; close it from that project" }],
  "browsers": { ... }
}

A gate that runs code from before this tool does not report closeVerb in its status, so close is refused on it until it goes idle and exits.

5. Lifecycle and idle stop

  • There is one gate process per project. It listens on 127.0.0.1 only, on the port in .playwriter/port (range 9400-9899).
  • Chrome debugs on 127.0.0.1 at the port in .playwriter/debug-port (range 9900-10399).
  • When a request arrives and no browser is up, the gate starts Chrome on the profile.
  • When nothing has come through for the idle time, the gate closes Chrome.
  • The gate exits after the idle time with no agent attached (an MCP session or a CLI command is running) and the browser stopped. The next tool call starts everything again on the same profile.

What an idle stop changes

  • Tabs are closed on an idle stop. Open the page again in the next call.
  • Cookies with no expiry (session cookies) do not survive a stop. Persistent cookies and the profile do.

A pause longer than the idle time closes the browser. Its tabs close with it.

Which folder is the project

  1. PLAYWRITER_PROJECT_DIR, if it is set.
  2. The nearest folder that holds .playwriter, searched from the current directory upwards.
  3. The nearest folder that holds .git, searched the same way.
  4. The current directory.

A folder with its own .playwriter is a project even inside a larger one, because the nearest match wins. Remove a stray .playwriter folder from a subdirectory to join its root project again.

Adopted browsers

The gate records the pid of each Chrome it starts, in .playwriter/browser.pid. When a gate starts and finds a browser already on its debug port, it adopts that browser. If the browser's pid is not the recorded one, status shows "adopted": true with a warning, and gate.log gets the same warning. Another browser may then share this project. The gate does not stop an adopted browser, so stop it yourself. The browsers tool refuses to close an adopted browser.

A new gate that adopts the browser its earlier gate started is not flagged, because the pid matches. Windows is not checked, since the pid lookup is not implemented there.

Add .playwriter/ to the project's .gitignore. The folder holds the profile, with its cookies and logins.

7. Environment

VariableUse
PLAYWRITER_PROJECT_DIRProject root. Without it, the project is found as described in chapter 5.
PLAYWRITER_BROWSER_PATHBrowser binary to start.
PLAYWRITER_NO_SANDBOX=1Passes --no-sandbox to Chrome.
PLAYWRITER_IDLE_MSIdle time in milliseconds. The default is 300000.
PLAYWRITER_TELEMETRY=0Turns off the relay's telemetry. DO_NOT_TRACK=1 also works. The relay reads it when it starts.

Headed or headless

On Linux, the browser is headless when neither DISPLAY nor WAYLAND_DISPLAY is set. Otherwise it is headed.

8. Limits

  • Windows is not covered. The browser scan does not run there, and the browsers tool refuses to close. macOS is scanned with ps and is not tested.
  • Concurrent agents in one project share one gate and one browser. That is not stress-tested.
  • A project moved to another path keeps its profile, because the profile is inside the folder. It gets a new gate and debug port only if the port files are missing.

The debug port is open on 127.0.0.1 with no authentication. Any local process can drive the browser.

9. Troubleshooting

Errors from the wrapper print to stderr, as playwriter-project: error: followed by the message. A browser start failure is not printed by the gate. The gate answers the failed request with HTTP 503, and the message is the body of that answer, so the agent sees it as the tool error. gate.log does not record it.

MessageWhat to do
playwriter-project: playwriter is not installed next to this package. Run npm install in the package folder.Run npm install in the package folder, or reinstall with add-mcp.
browser refused to start: no usable sandbox. Set PLAYWRITER_NO_SANDBOX=1 and restart the agent (manual, chapter 9).Add --env PLAYWRITER_NO_SANDBOX=1 to the add-mcp command, then run it again.
browser did not open debug port N; see .playwriter/browser.logRead browser.log. The message gives the full path of that file.
browser install failed (exit N); see .playwriter/browser.logCheck the network. Then run playwriter-project start to retry.
no free port in 9400-9899Another program holds the range. Free a port, or delete .playwriter/port in that project to pick another.
no free port in 9900-10399Another program holds the debug range. Free a port, or delete .playwriter/debug-port in that project to pick another.
gate did not start on port N; see .playwriter/gate.logRead gate.log. The message gives the full path of that file.
playwriter-project: error: port N is the gate for X, not Y. Delete .../port to pick a new port.The port file in this folder points at another project's gate, so this folder was not started. Delete .playwriter/port here, then run the command again.
WARNING browser pid P on debug port D is not the recorded pid R (gate.log, and status as ADOPTED)Another browser is on this project's debug port. Find it with status --json and stop it. The gate does not stop it.
playwriter-project: no gate running for XNo gate is running. This is not an error. The next tool call or start starts one.
browsers: not scanned, Windows is not coveredThe browser scan does not run on Windows, so the browsers tool does not close there. Use the browser's own window or the system's process list.
{"closed": false, "reason": "N other lease(s) held"}Another session in this project holds a lease. Close that session, or pass force to close anyway. A forced close drops that session's connection to the browser. The reply lists the lease pids.
pid P belongs to gate pid G for X; close it from that projectThe browser belongs to another project. Close it from project X, or leave it.
pid P is not started by pw (owner none)A default or other browser. The tool does not close it.
this project's gate runs code from before the browsers toolThe gate is replaced when it goes idle. Wait for it to exit, then run the command again.
playwriter-project: error: ...Read the message. gate.log is the record.

10. Update and remove

Update

If an agent still runs an older copy, npx has kept it in its cache. Delete the npx cache, then start the agent again:

rm -rf ~/.npm/_npx

Pin a version

Put a tag in the spec. v0.1.0 is the first tag:

npx -y add-mcp "npx -y github:AnEntrypoint/pw#v0.1.0" -n playwriter --all -g -y

Remove

npx -y add-mcp remove playwriter -g -y

That command removes the entry from the global configs. Delete each project's .playwriter/ folder to drop its profile. Both steps are optional.

Outside the project folder, the install writes the agent configs that add-mcp edits, the npx cache, ~/.playwriter/browsers when a browser is installed on first use, and ~/.playwriter/telemetry-id unless telemetry is off.
